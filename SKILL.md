# Green-wireframe explainer

A code-rendered 9:16 explainer: near-black stage, one lime accent, isometric
wireframe diagrams, dot-matrix HUD, and a bold caption that never shows more than
two short lines. Every shot carries exactly one idea. Nothing is filmed, nothing
is generated by an AI video model — it is drawn frame by frame.

`reference.md` (next to this file) holds every measurement behind the style and
the full template catalog. Read it once, then work from it.

## Setup in a new project

```bash
node -v                      # 18 or newer
ffmpeg -version              # any recent build on PATH
bash scripts/install.sh .    # copies this skill to ./.agents/skills/wireframe-explainer
```

`render.mjs` installs `@napi-rs/canvas` into the skill folder by itself on the
first run, so no project-level npm setup is needed. If that fails, run
`npm i @napi-rs/canvas` inside the skill folder. Without `install.sh`, the skill
still works from wherever it was cloned — run `node render.mjs` from the clone.

## When the user asks for a video

1. **Write the story first, in six chapters.** Hook → context → mechanism → the
   cost → the turn → the answer. One sentence per shot, and that sentence is the
   caption. Never write a paragraph and then cut it up.
2. **Pick one template per shot** from the catalog in `reference.md`. If an idea
   has no template, use the closest one; `card` with a big dot-matrix word is
   always a legal fallback.
3. **Write `film.json`** (schema below; worked example:
   `examples/containers.film.json`).
4. **Render stills first**: `node render.mjs film.json --stills --outdir stills`.
   Look at them. Fix overlaps, over-long captions, dead frames. Never render the
   whole video before the stills look right.
5. **Render the video**: `node render.mjs film.json out/film.mp4 [--music bed.mp3]`.
   About 24 rendered frames per second, so a 3-minute film takes ~4 minutes.
6. **Check the mp4** with `ffprobe` plus a few extracted frames, then hand over
   the path with the runtime and the shot count.

```bash
cd .agents/skills/wireframe-explainer
node render.mjs examples/containers.film.json out/containers.mp4   # 17 shots, 48.8 s
```

## film.json

```json
{
  "size": [720, 1280], "fps": 30,
  "chapters": [{ "badge": "1956", "label": "THE QUESTION", "step": 1, "of": 6 }],
  "shots": [
    {
      "ch": 0,                 // index into chapters (drives the top-left HUD)
      "tpl": "compare",        // template name, see reference.md
      "dur": 3.2,              // 1.5-4.5 s (mean 2.7)
      "props": { },
      "lines": ["ONE SHIP", "TOOK SIX DAYS"],   // 1-3 caption lines
      "annot": "PORT NEWARK · 1966",            // optional dot-matrix line, top centre
      "big": { "text": "SPEED", "y": 340 },     // optional big dot-matrix word
      "enter": "pop",          // pop (default) | hard | fade
      "fade": true             // optional fade in/out on this shot
    }
  ]
}
```

A caption line can carry keywords: `{"text": "SO HE CHOSE SPEED", "hi": ["SPEED"]}`
paints those words lime; `{"text": "...", "color": "lime"}` paints the whole line.
`\n` inside a line makes a two-row block.

## The rules that make it look like the reference

- **One idea per shot.** If a shot needs two diagrams, it is two shots.
- **2-4 words per caption line, 10-15 characters.** 62 px bold sans, white,
  centred, bottom-aligned at 80.5 % height, line step 1.3. Keyword in lime.
- **Lines advance inside the shot**, they do not all sit on screen: 1.0-1.6 s
  each, hard swap with a 120 ms pop. This is what keeps a still shot alive.
- **Mean shot length 2.7 s**, 20-22 cuts per minute, hard cuts only.
- **The HUD is continuity**: chapter badge (year or number, 44 px dot-matrix,
  lime), chapter label under it, six progress ticks. It changes only when the
  chapter changes.
- **Motion is small and continuous**: objects scale/fade in over 0.45 s, layers
  assemble bottom-up, counters tick, a walker walks, a needle sweeps, a sweep bar
  crosses a pixel field. No camera moves, no rotation showmanship.
- **Red is only for failure, loss, conflict.** Lime is the accent; everything else
  is white or grey. Never introduce a third hue.
- **Empty space is the design.** Geometry occupies the middle third; HUD at the
  top, caption at the bottom. If a frame feels full, delete an element.
- **Uppercase Latin only** in the dot-matrix layer (A-Z, 0-9 and basic
  punctuation). Captions are a normal sans font and take accents fine.

## Do not

- Do not use real footage, AI-generated video, stock images, or fonts other than
  the bundled dot-matrix renderer and the caption sans.
- Do not put a wall of text on screen, and do not caption what the diagram
  already says word for word.
- Do not add sound design unless asked; one music bed via `--music` is enough.
- Do not ship without looking at the stills.
